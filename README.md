# 제주 데이터 길잡이 — 묻고, 찾고, 계산하고, 확인하는 데이터 AI Agent

제주 AI·빅데이터 활용 AI Agent 개발 챌린지 출품작(소병권). 제주데이터허브의 공개 데이터에 **우리말 질문 한 줄**을 던지면, 맞는 데이터를 찾고 · 질문 속 대상이 그 데이터에 정말 있는지 확인하고 · 이 질문에 쓸 수 있는지 점검하고 · 계산하고 · **원본 파일에서 다른 방식으로 다시 계산**해 숫자를 맞춰 보고 · 숫자마다 **어느 칸에서 왔는지** 보여 줍니다. 모르는 것은 이유와 함께 거절하거나 되묻습니다.

- 설치 없음 · 서버 없음 · **의존 라이브러리 0개**(순수 HTML/JavaScript) · **인터넷·GPU·AI 키 불필요**
- 서비스 안에 생성형 AI 모델이 **없습니다**(규칙 기반) → 서비스에 쓰는 LLM **프롬프트도 없습니다**. 질문 해석 규칙은 `js/understand.js`·`js/agent.js`·`js/catalog.js` 에 코드로 들어 있습니다. 같은 질문에는 항상 같은 답이 나옵니다(재현성).

## 1. 실행 방법(센터 PC: i7-8700 / GTX1060 / RAM 32GB 기준, 브라우저만 있으면 됩니다)
| 방법 | 순서 |
|---|---|
| ① 가장 쉬움 | `dist/jeju-guide.html` 을 **더블클릭**(크롬·엣지·파이어폭스). 데이터 333종이 한 파일에 들어 있습니다(약 5MB). |
| ② 개발용 | `node serve.mjs` → http://localhost:8080 (`index.html` + `js/` + `data/`) |
| ③ 묶음 다시 만들기 | `node build-single.mjs` → `dist/jeju-guide.html` |

- 환경변수: **필요 없음**(`.env.example` 참고). 허브 프로젝트 키는 코드에 없으며, 전체 데이터로 갱신할 때 데이터 파일 교체에만 쓰는 선택 사항입니다.
- 의존성: 앱은 없음. 시험에는 Node.js 20+(`node --version`), 정답 만들기에는 Python 3(표준 라이브러리 `csv`·`json` 뿐).
- 화면 사용법은 `사용자매뉴얼.pdf`, 데이터 사용 내역은 `데이터활용명세.md/.csv`, 구조·시험 결과는 `결과설명자료.pdf`, 기획 전체는 `AI_Agent_기획서_제주데이터길잡이.pdf` 를 보세요.

## 2. 데이터
- `data/catalog.json` — 제주데이터허브 카탈로그 **1,259종** 메타데이터(제목·설명·분야·기간·제공처·인증 여부), 로그인 없이 공개된 JSON(2026-10-29 수집).
- `data/raw/<허브 데이터 번호>.csv` — 허브가 **로그인 없이 내려받게 열어 둔** 데이터 **333종(50,759행, 3.8MB)** 의 첨부 CSV(UTF-8 변환, 값은 수정하지 않음).
- `data/manifest.json` — 파일별 원본 파일명·크기·행 수·SHA-256(앞 16자)·수집일·허브 페이지·**자료 안의 실제 기간**.
- 허브 ‘미리보기/샘플’ 파일(333종 중 138종)은 전체의 일부일 수 있고, 앱이 질문마다 알립니다. 로그인이 필요한 926종은 이 PC에 파일이 없으며 “없다”고 밝힙니다. 출처·이용조건·전처리는 `데이터활용명세.md`.

## 3. 구조(Agent 워크플로)
```
질문 → search_catalog(카탈로그+표 안 열·값 색인)
     → understand_question(핵심어 뽑기, 원인·예측·개수·추천·기준 시점 없는 비교는 앞질러 거절)
     → inspect_and_plan(열 역할·조건·기간·연산, 후보를 차례로 시도) + acceptance_check(핵심어가 표 제목·열·값에 있어야 진행)
     → ambiguity_check(구분 열에 단위가 다른 항목이 섞이면 되묻기)
     → suitability_gate(신호등: 기간 밖·미리보기·최신성·빈 칸·구분 합침·달 수 불일치·쌓여 있는 양 합산)
     → execute(근거 칸 기록) → verify_calculation(원본 CSV 글자에서 다른 방식으로 재계산)
     → compose(‘이렇게 이해했어요’ 한 줄·쉬운 말 답·그래프·근거 표)
```
| 파일 | 역할 |
|---|---|
| `js/catalog.js` | 데이터 찾기(어절·조사·동의어·글자쌍) |
| `js/understand.js` | 질문 핵심어·표 글자와의 대조·되물어야 하는 질문 유형 |
| `js/table.js` | CSV 읽기·열 종류 추정·가로 월 표 세로 변환·CP949 해석 |
| `js/agent.js` | 질문 해석(plan)·계산(execute)·쉬운 말 답(compose)·‘이렇게 이해했어요’ |
| `js/verify.js` | **계산 검증**(agent.js·table.js 를 쓰지 않는 두 번째 구현) |
| `js/pipeline.js` | 한 번의 질문 처리·적합성 게이트·작업 기록·내 파일 올리기 |
| `js/app.js`·`index.html`·`css/` | 화면(innerHTML 없이 DOM 생성) |
| `build-single.mjs` | 한 파일 묶음 → `dist/jeju-guide.html` |
| `enrich_manifest.mjs` | 파일 안의 실제 기간·열 이름을 manifest 에 기록 |

## 4. 시험(정답은 에이전트와 별개의 경로로 만든 것)
```
node test/units.test.mjs          # 10개: CP949 해석·열 이름 중복·핵심어·상대 연도·앞질러 거절
node test/catalog.test.mjs        # 14개: 질문 → 기대 데이터가 상위 5위 안
node test/golden.test.mjs         # 21개: 골든 질문(정답 = python test/make_golden.py 가 원본 CSV 에서 독립 계산)
node test/heldout.test.mjs        # 13개: 튜닝 전에 따로 만든 새 질문 (첫 실행 10/13, test/heldout_first_run.txt)
node test/heldout2.test.mjs       # 21개: 앱을 돌려 보기 전에 ‘평범한 말투’로 쓴 질문 (첫 실행 14/21 → 정답지 오류 3건 정정 후 재채점 11/21, test/heldout2_first_run.txt·heldout2_corrections.txt)
node test/negative.test.mjs       # 47개: 답하면 안 되는 질문 35 + 자료 기간 밖 4 + 밝힘 7 + 데이터 333종 퍼지 666건
node test/fit.test.mjs            # 8개: 계산은 맞지만 질문과 다른 답(엉뚱한 열·‘어느 해’인데 항목별 값·‘A가 B보다’의 한쪽 누락·‘가장 최근’)을 막는 회귀 시험
node --expose-gc test/bench.mjs   # 시작·질문당 시간·메모리
```
- 오늘 날짜는 시험에서 2026-10-29 로 고정합니다(‘올해·작년’ 계산이 날짜에 따라 달라지므로).
- **정직한 주석**: 골든 21개와 부정 시험 앞쪽의 질문은 통과시키며 규칙을 고쳤으므로 회귀 시험입니다. held-out 13개는 처음 10/13, held-out 2의 21개는 처음 14/21 이었고(실패 원인: 질문 속 틀 말을 대상으로 오인 · ‘비율이’ 오검출 · 형용사/단위/한 글자 값 해석), 원인을 고친 뒤 통과했습니다. 첫 실행 기록 원문을 그대로 남겼습니다. 나중에 **정답지 자체의 오류 3건**(건강관련통계정보의 0 이 ‘미조사’ 표시인데 값 0 으로 읽음)을 발견해 정정했고, 정정한 정답지로 첫 실행을 다시 채점하면 11/21 입니다(`test/heldout2_corrections.txt`).
- 계산 검증은 개발 중 환경소음 묶음 방식, 따옴표 속 줄바꿈이 있는 CSV, 열 이름 중복 처리의 실제 불일치를 잡았습니다.
- 개발 중 독립 점검에서 지적된 ‘엉뚱한 데이터로 초록불 오답’(한라산 탐방객·전기차 충전소·서귀포 관광객·렌터카 대수·코로나 전후·올해 감귤 생산 등)은 부정 시험으로 고정했습니다.

## 5. 오류·제약
- 질문 해석은 규칙 기반이라 표현이 크게 달라지면 못 알아들을 수 있습니다 → 거절·되묻기로 처리합니다. 질문 속 대상(예: ‘한라산’)이 고른 표의 제목·열 이름·짧은 값에 없으면 답하지 않으므로, 표에 영문 열 이름만 있는 자료(예: 기후 `Tem_mean`)는 한국어 질문에 답하지 못할 수 있습니다.
- 지원: 합계·평균·최대/최소·상위 N·증감률·추이·비교(연·월·계절·최근 N 기간). 미지원: 개수 세기, 비중, 상관·원인·예측, ‘코로나 전후’처럼 기준 시점이 말뿐인 비교(연도를 알려 주면 계산), 지도·좌표 분석, 두 데이터 결합.
- 소음·물가·온도·점수 같은 **수준 값은 더하지 않고** 평균·최댓값으로 계산합니다(화면에 안내). 질문에 없는 ‘구분’ 값을 모두 합친 경우, 기간을 말하지 않아 자료 전체를 합친 경우, 해마다 달 수가 다른 경우, 인구 같은 ‘쌓여 있는 양’을 여러 시점 합산한 경우는 주황 신호등과 답 문장 안의 ※ 로 알립니다.
- 계산 검증은 **계산이 맞는지만** 확인합니다. 질문을 맞게 이해했는지는 답 위의 ‘이렇게 이해했어요’ 줄로 사용자가 확인해야 합니다.
- 비고·특이사항 열에 ‘미조사·미집계’ 가 적힌 표(예: 건강관련통계정보)의 **0 은 값으로 쓰지 않습니다**(조사하지 않은 칸을 0 으로 채운 경우가 많음). 그 칸만 남으면 숫자 대신 이유를 알려 줍니다. 비고가 칸마다 어긋나 있는 표라 완전히 가려내지는 못합니다.
- 단위는 일부 데이터만 알고 있습니다(`data/hints.json`), 나머지는 숫자만 표시합니다.
- 올린 CSV 는 UTF-8 이 아니면 CP949(엑셀 한글 CSV)로 읽습니다. 그 밖의 인코딩은 지원하지 않습니다.
- 센터 PC 실측은 하지 못했고(개발 PC Node 측정: 시작 0.3초·질문당 수 ms·메모리 약 140MB), 사양 대비 여유가 큽니다.
- 허브 이용안내의 데이터별 라이선스 문구(공공누리 유형 등)는 확인하지 못했습니다(`데이터활용명세.md` 2항).
